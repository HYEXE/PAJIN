# UX-010: Measured Product Deployment and Console

## Entry points

The ordinary `pajin-control-plane` and `python -m pajin.control_plane` entry points accept the
following optional pair of server-owned environment settings:

| Setting | Meaning |
| --- | --- |
| `PAJIN_CP_MEASURED_PRODUCT_DEPLOYMENT_PATH` | Absolute path to the private deployment inventory |
| `PAJIN_CP_MEASURED_PRODUCT_DEPLOYMENT_SHA256` | Lowercase SHA-256 of the exact inventory bytes |

`pajin-control-plane --check-config` or `python -m pajin.control_plane --check-config` checks
environment/TLS settings and reopens every selected result without starting a server or creating
the Control Plane database. Its JSON diagnostic names each domain as `verified` or `not-configured`.
Configured readers perform read-only Docker identity and residue queries; Docker and the exact
retained images must be available. An unconfigured optional domain is not a successful measurement.

Invalid pairs, relative paths, unavailable files, digest mismatch, duplicate JSON keys, invalid
schemas, unsafe durable paths, failed reconstruction, and failed source verification reject startup.
The safe error reports the failing stage without printing inventory contents or private paths.
Missing retained state is never created to make verification succeed. Graph, activation, route
claim, and Worker evidence stores must already satisfy their current integrity contracts; product
reads do not create, repair, or migrate them.

## Private inventory

`MeasuredProductDeployment` is `pajin.dev/measured-product-deployment/v1alpha1`, kind
`MeasuredProductDeployment`. It has `deploymentId`, `evidenceRoot`, and optional `web`, `network`,
and `ai` recipes. At least one recipe is required. The 32 MiB byte bound, strict JSON depth/node
bounds, exact existing paths beneath one canonical evidence root, and regular single-link files
are checked before runtime reconstruction. Existing signed authorities and code-owned registrations
remain authoritative. The inventory itself grants no Campaign Scope or execution authority.

For an already completed AI result, deployment preparation can use:

```python
from pajin.control_plane.measured_product_deployment import (
    MeasuredProductDeployment,
    write_measured_product_deployment,
)
from pajin.control_plane.measured_product_sources import AIProductRecipe

deployment = MeasuredProductDeployment(
    deploymentId="analysis-host",
    evidenceRoot=retained_evidence_root,
    ai=AIProductRecipe.from_outcome(completed_ai_outcome),
)
digest = write_measured_product_deployment(private_inventory_path, deployment)
```

`NetworkProductRecipe.from_outcome` provides the corresponding Network conversion.
`WebProductRecipe.from_outcome` additionally requires the existing complete reopen context,
provider state path, Worker evidence store path, target coordinate, and successful route context.
No new execution is performed during export. Export does not certify that an inventory will pass
preflight; run `--check-config` against its pinned digest before deployment.

Keep this inventory private. It retains Ground Truth and consumed approval/request material;
public keys are sufficient for verification and no measurement signing key is exported. The Web
terminal approval snapshot may only support completed-result verification. It cannot issue or
reissue an approval, Permit, route, or dispatch. New live execution must use its original authority
and freshness checks. Inventory replacement and key-policy changes require process restart.

## HTTP and Console behavior

Existing Operator-only, zero-input endpoints and their public response contracts remain unchanged:

- `/v1/products/web-measured-flow`
- `/v1/products/network-measured-service-identification`
- `/v1/products/ai-measured-system-prompt-disclosure`

Authentication/authorization still precede reader access. Unconfigured domains return 503;
subsequent source verification failures retain the existing 409 response. Every successful GET
reopens its source. There is no upload endpoint, factory parameter, provider selector, or cached
validation result. Injected readers and a configured inventory cannot be combined.

The Network and AI panels show public cases, exact metric counts, rational values, and the
synthetic-only limitation. They offer read and retry actions. They do not expose raw evidence,
private labels, credentials, runtime coordinates, a Finding confirmation, report delivery, or
execution controls. Credential generations own pending requests; lock or credential replacement
clears results, disables controls, and prevents stale responses from repopulating the view.

Browser validation constants come from `measured_product_browser_contract()` and are shipped in
`measured-product-contracts.js`. A regression test compares generated bytes to the packaged asset.
Changing public model membership requires regenerating and reviewing this asset together.

## Verification boundary

Configuration, serialization, unsafe path rejection, repeated reads, read-only provider behavior,
CLI dispatch, public asset packaging, and Console error/stale-state tests cover local integration.
The Web Docker conformance also exports this inventory and rebuilds its production reader and
Operator API in a separate process. The
exact current-commit Ubuntu Docker and residue gates remain necessary to claim live conformance.
