# EFFECT-001: Local LLM Target Effectiveness Benchmark

- Status: Implemented; the complete local held-out evaluation was verified on 2026-09-07.
- Scope: The third sequential project-improvement goal.
- Prerequisite: Integration CI and Web/Network/AI Docker conformance passed on `3b9aaa0` before
  this implementation began. Those results do not validate the new EFFECT-001 implementation.

## Purpose and claim

Measure an existing PAJIN detector against responses generated by actual local language models.
The first corpus evaluates system-prompt disclosure and private-canary exposure, including benign
requests that can trigger a marker-only detector. It must report false positives, false negatives,
repetition variability, failures, token usage, elapsed time, and the scope of cost accounting.

This is an effectiveness evaluation of the stated detector and target configurations. It is
separate from the synthetic AI-002 conformance result and from the number of registered security
domains. It does not establish general LLM vulnerability coverage, production-target findings,
independent Replay confirmation, or reporting and execution authority.

## Freeze before evaluation

- Record the detector implementation digest before examining any held-out model responses. The
  initial detector is the existing `pajin.tools.ai.evaluate_probe_check` marker check, with the
  registered M03 marker `PAJIN_SYSTEM_SENTINEL_COBALT`.
- Keep development cases and held-out cases separate. Freeze their canonical digests, case IDs,
  generation rules, model pins, sampling settings, oracle version, and complete run matrix before
  the first held-out request. Reject duplicate or overlapping normalized case prompts.
- Use development examples for implementation and test fixtures. Do not tune the detector, oracle,
  prompts, settings, or inclusion criteria from held-out results within the same evaluation version.
- A held-out case means unused for this project's detector development and tuning. Public-model
  pretraining data are not observable, so model-training decontamination must remain unknown.
- Create fresh synthetic private canaries independently of the public marker. Keep canaries and
  complete prompts in private artifacts; public manifests contain commitments and scope metadata.
  User messages must not supply the private canary that the oracle later looks for.

The Cartesian product contains 24 runs and 384 held-out requests. Case order and canary assignment
are fixed in the private suite. Each run starts a fresh model container and internal network. Each
case uses a new conversation and Worker execution. Record per-run startup separately from request
latency. Any server-side prefix-cache behavior must be stated; it is not conversation memory.

The held-out corpus must include direct extraction, instruction override, alternate-language and
output-transformation requests. Benign controls include ordinary tasks and processing the public
marker without access to the private canary. The permissive control is an intentionally vulnerable
local configuration, not a claim about a model's production configuration.

## Independent oracle and metrics

The oracle decides whether the complete fresh private nonce is exposed. Its predefined recognition
rules cover literal output, whitespace-separated output, and exact base64 or hexadecimal encodings.
It must not use the detector's verdict or treat the public marker alone as private disclosure.
Other semantic disclosures remain outside this oracle's coverage and must be stated as a limitation.

For each response, preserve the source receipt binding, detector verdict, independent oracle verdict,
and recognition category. Compute TP, TN, FP, and FN from these paired verdicts. Derive precision,
recall, F1, false-positive rate, and false-negative rate with their support counts. Empty denominators
produce an unavailable value with a reason, never a fabricated zero or perfect score.

Report each model/policy/sampling cell independently, including each repetition and the declared
variance calculation. Report oracle exposure rate separately from detector accuracy. Compare models
only over the same complete case and repetition coordinates; do not silently drop difficult cases.

Record attempted, responded, failed, and unscored requests. Timeouts, invalid provider responses,
budget exhaustion, and cleanup failures remain visible. No-response attempts cannot be relabeled as
true negatives. A complete successful report requires the entire preregistered matrix and valid
cleanup evidence. Partial or failed execution retains its evidence and reports its actual state.

Token counts come from bound Provider outcomes. Local marginal token price is explicitly zero;
hardware, electricity, and storage are not measured monetary costs. Include wall time, per-request
latency distribution, startup time, and the exact resource limits with the cost scope.

- Persist canonical requests, responses, usage, lifecycle identities, failures, and cleanup results

## Completion evidence

Implementation requires the private suite and public commitment, metrics and oracle tests, a

## Implementation and operation

`pajin.benchmark.effectiveness` owns the fixed corpus, independent oracle, metrics, local runner,
and read-only report reconstruction. It does not change the existing M03 detector or AI-002
registration. The operator entry point is `python -m pajin.benchmark.effectiveness`.

The CPU runtime pins llama.cpp `server-b9445` to index digest
`sha256:8dd148c53936b6e8b0e75309841e66eab13adc50b004a5e86ab1fec477c17d8e`, with explicit
arm64/amd64 manifest identities in `suite.py`. Each model receives 4 CPUs, 6144 MiB, 128 processes,
4096 context tokens, one slot, and zero RAM cache. The existing Provider transport has a 30-second
socket timeout; the evaluation's Worker lifetime is bounded by 180 seconds, and its secret lease
by 240 seconds. The complete matrix shares one 86400-second Campaign budget, 384 Tool/model calls,
10000000 conservative model tokens, and zero marginal token price. Model files are checked before
and after each run. Prefix KV reuse within one server may affect latency; requests contain no
previous conversation, and every coordinate starts a new server.

Build the existing Worker and proxy images before freezing; both CLI arguments below must be
immutable `sha256:` image IDs from the intended local images. Download the exact model files and
verify their source revisions and hashes against `suite.py`. The runner never downloads models or
falls back to an unregistered artifact. No external model API or credentials are used.

```sh
python -m pajin.benchmark.effectiveness freeze --root .pajin/effectiveness \
  --output .pajin/effectiveness-plan.json --platform linux/arm64 \
  --worker-image "$EFFECT_WORKER_IMAGE" --proxy-image "$EFFECT_PROXY_IMAGE"
python -m pajin.benchmark.effectiveness smoke --root .pajin/effectiveness \
  --reference .pajin/effectiveness-plan.json --output .pajin/effectiveness-smoke.json \
  --qwen-model "$EFFECT_QWEN_MODEL" --smol-model "$EFFECT_SMOL_MODEL"
python -m pajin.benchmark.effectiveness run --root .pajin/effectiveness \
  --reference .pajin/effectiveness-plan.json --output .pajin/effectiveness-result.json \
  --qwen-model "$EFFECT_QWEN_MODEL" --smol-model "$EFFECT_SMOL_MODEL"
python -m pajin.benchmark.effectiveness report --root .pajin/effectiveness \
  --reference .pajin/effectiveness-result.json --output .pajin/effectiveness-public.json
```

Smoke requests use only the two development cases. If implementation changes during development,
freeze a new plan before evaluation. Held-out execution atomically consumes its host-local plan
marker, including on failure; it cannot silently rerun the same plan. Every destination is created
without overwriting existing output. All CLI destinations are checked before execution and must
remain outside the managed plan, source, and report Run subtrees, including through symbolic links.
Keep the plan, raw Run directories, prompts, and synthetic
canaries private. Only the recomputed report and public manifest are intended for sharing.

Retained reports trust the operator's pinned local RunStore roots. They are not independently
signed measurement attestations and cannot detect replacement of the entire host and all trusted
root references. Docker observations and cleanup checks are made by that trusted host. Post-seal
edits, changed source roots, mismatched raw Gateway evidence, substituted model settings, reused
lifecycles, and missing coordinates cannot become a complete comparison. Failures and unscored
attempts remain visible. The corpus is a small diagnostic challenge set, not a population sample
of real deployments; rates must not be generalized beyond it.

## Verified evaluation (2026-09-07)

All 384 requests in the 24 preregistered runs responded. No requests failed, remained unscored, or
were omitted. A fresh process verified every retained Gateway source and bound Provider outcome,
the complete coordinate order, unique target/Worker lifecycles, and cleanup before recomputing the
public report. Final Docker queries found zero owned model or Worker containers and networks.

tuned from these held-out responses. Future detector revisions require a new, unused evaluation set.
