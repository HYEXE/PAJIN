# ADR 0018: CTF Crypto Mode를 위한 제한된 인라인 아티팩트

- 상태: 승인됨
- 날짜: 2026-07-13

## 배경

첫 번째 CTF 단면은 하나의 Web Specialist를 입증하지만 아직 범주 인식 라우팅이나 오프라인 분석
워크플로는 입증하지 않는다. Pwn, 리버싱, 포렌식 및 일반 암호학에는 보통 파일과 폭넓은 Tool이
필요하다. PAJIN이 신뢰할 수 있는 아티팩트 서비스와 Tool별 파일 시스템 capability를 갖추기 전에
임의의 호스트 경로, Worker 바인드 마운트, 셸 명령 또는 제한 없는 무차별 대입을 추가하면 안전
경계가 확대된다.

PAJIN에는 네트워크 접근, 외부 프로세스 또는 사용자가 선택한 파일을 도입하지 않으면서 아티팩트
무결성과 오프라인 계산을 실행하는 두 번째 범주가 필요하다.

## 결정

PAJIN에 제한된 인라인 아티팩트 계약을 갖춘 `crypto.single-byte-xor` 시나리오를 추가한다.

- 인코딩은 정확히 소문자 16진수다.
- 디코딩된 크기는 1바이트 이상 4 KiB 이하다.
- 매니페스트는 디코딩된 바이트의 SHA-256을 제공한다.
- 미디어 타입은 `application/octet-stream`으로 고정한다.
- 범위, 호스트 경로, URL, 명령 및 실행 파일은 금지한다.
- 예상 플래그는 별도의 SHA-256으로 유지되며 Specialist Tool 입력에 절대 들어가지 않는다.

매니페스트 검증은 아티팩트를 디코딩하고 상수 시간 다이제스트 비교를 수행한다. 컴파일러는 논리적
정책 대상으로 `http://artifact.invalid/<challenge>/<artifact-sha256>`를 파생한다. 이 URL은
네트워크 목적지가 아니라 현재의 일반 범위 엔진과 호환되는 ID다. Crypto Tool은
`network_access: false`를 선언하고 Campaign은 네트워크 접근을 금지하며, 그 결과 생성된 Docker
Worker Job은 이그레스 정책 없이 `network: none`을 유지한다.

Triage Planner는 타입이 지정된 Crypto 범주/시나리오 쌍만 `ctf.crypto-single-byte-xor`에
매핑한다. Tool은 디스패치 전에 POST 의미 체계, 파생된 콘텐츠 주소, 크기, 16진수 문법 및
아티팩트 다이제스트를 검증한다. 고정 Worker 명령에는 논리적 대상, 챌린지와 시나리오 ID,
아티팩트 다이제스트 및 암호문만 전달한다.

Worker는 모든 검증을 반복한 다음 프로세스 내부에서 정확히 0부터 255까지의 유한 키 공간을
평가한다. 셸, 서브프로세스, 패키지 관리자, 모델, MCP 서버 또는 네트워크 API를 호출하지 않는다.
완전한 `PAJIN{...}` 문법과 일치하는 ASCII 평문만 유지한다. 일치 항목이 0개이면 해결되지 않은
관찰 결과를 생성하고, 2개 이상이면 모호한 것으로 간주하여 안전하게 실패한다.

기존 Mode별 다이제스트 Validator는 관찰 결과를 다시 파싱하고 아티팩트와 챌린지 ID를 검증하며,
동일 Run의 증거를 요구하고, 후보를 해시하여 예상 다이제스트와 대조한다. 일반 러너는 여전히
대상과 증거의 결합을 강제한다. `CTFModePack`은 범주별 라우트와 오프라인 분석 세부 정보를
포함하여 Web에서 사용하는 것과 동일한 결과 및 풀이 문서 스키마를 방출한 다음 무결성 확장
봉인을 추가한다.

`ctf-run`은 범주 인식 CLI가 된다. `ctf-web-run`은 Web 전용 별칭으로 계속 제공되며 Worker를
선택하기 전에 Crypto 매니페스트를 거부한다. 어느 명령도 스코어보드에 제출하지 않는다.

## 결과

이 설계는 일반 파일 시스템이나 명령 실행 권한을 부여하지 않으면서 두 번째 Specialist 범주,
콘텐츠 주소 기반 아티팩트 검증, 오프라인 Worker 격리, 유한 계산, 독립적인 플래그 검증 및 공통
보고를 입증한다.

인라인 16진수는 작은 공개 챌린지 아티팩트를 매니페스트, Campaign 및 Worker 입력에 중복해서
담는다. 이는 제한된 합성 픽스처에만 적합하며 대형 바이너리나 민감한 데이터에는 적합하지 않다.
향후 리버싱, Pwn 및 포렌식 지원에서는 이 인라인 한도를 늘리는 대신 별도로 설계한 불변 아티팩트
서비스, 미디어별 파서, 읽기 전용 Worker 마운트, 압축 해제 한도 및 명시적인 파일 시스템
capability를 도입해야 한다.

## 검증

테스트는 Web/Crypto 범주 쌍, 다이제스트 불일치 및 비정규 16진수 거부, 파생된 아티팩트 ID,
T0 및 이그레스 없는 정책 컴파일, 고정 Tool 입력, Worker 측 다이제스트 검증, 전체 256개 키 평가,
범주별 Specialist 라우팅, 독립적인 `CTF-CRYPTO` 검증, 두 번의 봉인을 통한 결과 최종화, 일반
CLI 라우팅 및 Web 별칭 거부를 다룬다.
