# ADR 0022: 동일 출처 Control Plane Web Console

- 상태: Accepted
- 날짜: 2026-07-14
- 확장 문서: [ADR 0023](0023-fenced-control-plane-actions.ko.md)

## 맥락

ADR 0011과 ADR 0012는 인증을 적용한 내구성 있는 Control Plane과 리스를 인식하는 Worker
데몬을 제공하지만, 운영에는 여전히 직접적인 API 호출이 필요하다. 첫 번째 제품 UI는 기존 역할
경계를 약화하거나 두 번째 인증 시스템을 도입하지 않으면서 등록된 Job을 제출하고, 내구성 있는
Run 상태를 보여 주며, 추가 전용 이벤트 추적 기록을 공개해야 한다.

브라우저는 일반적인 페이지 탐색에 `Authorization` 헤더를 첨부할 수 없다. 불투명 Bearer 자격
증명을 URL, 쿠키, 서버 렌더링 폼, 브라우저 저장소 또는 빌드 시점 자산에 넣으면 새로운 유출,
CSRF, 세션, 보존 위험이 생긴다. 별도의 프런트엔드 출처를 사용하면 테넌트 격리가 마련되기도 전에
CORS와 추가 배포 경계가 필요하다.

Run 입력에는 민감한 평가 구성이 포함될 수 있고 크기도 클 수 있다. 대시보드 목록의 모든 행에
이를 반환하면 정보 노출과 데이터베이스 리소스 비용이 모두 늘어난다. 따라서 기존 `RunView`는
목록 DTO로 적합하지 않다.

## 결정

FastAPI Control Plane은 패키징된 `importlib.resources`에서 의존성 없는 HTML, CSS,
JavaScript Console을 `/ui`로 제공한다. 공개 셸에는 Run 데이터, 자격 증명, 인라인 스크립트,
인라인 스타일 또는 외부 리소스가 없다. 모든 상태는 기존 동일 출처 `/v1` API 뒤에 유지된다.

Console은 Bearer 자격 증명을 JavaScript 모듈 변수에만 보관한다. 쿠키, `localStorage`,
`sessionStorage`, IndexedDB, URL, DOM 속성 또는 콘솔 로깅은 사용하지 않는다. 잠금, 페이지
종료, HTTP 401 응답 시 값을 지운다. Fetch 호출은 고정된 동일 출처 경로를 사용하고 자격 증명을
생략하며 캐싱과 리디렉션을 비활성화하고, 명시적으로 연결한 뒤에만 Bearer 헤더를 첨부한다.
모든 요청과 상태 갱신은 단조 증가하는 자격 증명 세대에 귀속된다. 잠금 또는 자격 증명 교체는
진행 중인 Fetch를 취소하며, 전송 계층을 취소할 수 없더라도 이전 세대의 지연된 성공 응답이나
HTTP 401 응답은 폐기한다.

`GET /v1/session`은 Operator, Approver 또는 Auditor 자격 증명에 인증된 주체와 역할을
반환한다. UI는 Operator에게만 제출 기능을 활성화하며 서버 측 역할 검사가 최종 기준이다.
Worker 자격 증명은 세션, Run 목록, 세부 정보 또는 이벤트 엔드포인트에 접근할 수 없다.

`GET /v1/runs`는 `RunSummaryView` 항목, 전체 개수, limit, offset을 포함한 `RunListView`를
반환한다.

- `input`, 제출 키, Job 페이로드/결과, 리스 필드는 포함하지 않는다.
- SQLAlchemy는 입력 열을 로드한 뒤 버리는 대신 로드를 연기한다.
- 상태 필터링은 서버에서 정의한다.
- 정렬은 `updated_at DESC, run_id DESC`로 고정한다.
- limit은 1~100, offset은 0~10,000이다.

첫 번째 UI 범위는 멱등적인 Run 제출, 제한된 목록 조회, 선택한 Run의 세부 정보, 추가 전용 이벤트
추적 기록을 지원한다. 폴링은 명시적으로 실행하거나 5초 간격으로 실행한다. 이 결정 시점에는 승인
결정, 체크포인트 재개, 취소, 보고서 다운로드, Agent Graph, SSE, WebSocket을 제외한다.
ADR 0023은 나중에 이 브라우저 경계를 바꾸지 않고 처음 세 작업을 추가한다.

이벤트 추적 기록은 화면에서만 잘라 보이는 무제한 응답이 아니라 제한된 시퀀스 페이지다. API는
최신 이벤트를 오름차순으로 최대 200개 반환하고, 배타적 `before` 시퀀스 커서를 받으며, 직렬화된
응답을 4 MiB 이하로 제한한다. Console은 숨겨진 전체 이력을 다운로드하지 않고 Latest와 Older
탐색을 제공한다.

HTML 응답에는 동일 출처 스크립트, 스타일, API 연결만 허용하는 제한적인 CSP를 적용한다. 인라인
속성, 객체, Worker, 프레이밍, 기본 URL, 폼 탐색은 거부한다. UI와 API 응답에는 no-store 및
no-referrer 정책을 사용한다. UI 렌더링은 DOM 노드를 생성하고 `textContent`를 할당하며,
신뢰할 수 없는 응답 값을 HTML로 해석하지 않는다.

편집 가능 설치, wheel, 읽기 전용 Control Plane 컨테이너가 같은 리소스를 사용하도록 자산을
setuptools 패키지 데이터로 선언한다. npm, CDN, 템플릿 엔진 또는 런타임 파일 시스템 쓰기는
필요하지 않다.

## 결과

- 로컬 Operator는 API 호출을 수동으로 구성하지 않고도 내구성 있는 Run을 제출하고 모니터링할
  수 있다.
- 이 첫 번째 범위는 Approver와 Auditor 자격 증명에 읽기 전용 Console을 제공한다. ADR 0023은
  나중에 역할로 제한되는 Approver 결정을 추가하지만 Auditor 접근은 읽기 전용으로 유지한다.
- 잠금이 해제된 동안 브라우저는 평문 토큰을 메모리에 보관하므로 XSS, 권한 있는 확장 프로그램,
  DevTools가 이를 읽을 수 있다. CSP, 외부 자산 배제, 동일 출처 제공, HTTPS는 이 위험을 줄이지만
  없애지는 못한다.
- 셸은 의도적으로 공개하지만 모든 데이터 작업에는 계속 인증이 필요하다. 배포 환경은 `/ui` 접근을
  인증으로 간주해서는 안 된다.
- 오프셋 페이지네이션은 제한되어 있으며 로컬 프리뷰에 충분하다. 대규모 플릿은 안정적인 키셋
  커서로 전환하고 관리형 데이터베이스 인덱스를 추가해야 한다.
- 감사 이벤트는 제한된 배타적 시퀀스 페이지네이션을 사용한다. 로컬 Console은 클라이언트에
  무제한 이력을 누적하는 대신 최신 페이지로 바로 돌아간다.
- 현재 자격 증명과 Run 소유권은 테넌트 범위가 아닌 전역 RBAC이다. ID, 테넌트 소유권, 해당하는
  경우의 CSRF/세션 정책, TLS, 권한 격리를 별도로 설계하고 테스트하기 전까지 원격 또는 다중
  테넌트 노출을 금지한다.

## 검증

자동화된 테스트는 역할 분리, 안정적인 필터링 및 페이지네이션, 쿼리 경계, 요약 필드 최소화,
읽기 전용 목록 조회, 멱등적 제출, CSP 및 보안 헤더, 공개 셸과 인증된 데이터의 분리, 영구 자격
증명 API와 안전하지 않은 DOM 싱크의 부재, 기본 실행기 입력, 패키징된 자산 로딩을 검증한다.
wheel 검사는 정적 자산 5개(`index.html`, `app.css`, `app.js`, `protocol.js`,
`render.js`)가 모두 포함되었는지 검증한다. 데스크톱 및 소형 헤드리스 브라우저 렌더링은
반응형 셸 레이아웃을 검증한다. 외부 의존성이 없는 JavaScript 런타임 하네스는 인증
교체와 잠금, 지연 응답 폐기, 갱신·페이지네이션 경쟁, 유효하지 않거나 빈 응답, 정확한 64비트
JSON 표시, 역할·상태별 작업 게이트를 검증한다.
