# ADR 0016: 변조 흔적을 드러내는 Run 무결성 체인

- 상태: 승인됨
- 날짜: 2026-07-13

## 배경

PAJIN은 Finding이 해당 Run 디렉터리 안의 증거를 인용하는지 검증하지만, 경로 포함 여부만으로는
실행 후 변경된 파일을 탐지할 수 없다. Audit Event는 관례상 추가 전용이었을 뿐 암호학적 순서
연결이 없었다. 이 때문에 모든 Mode Pack이 실수로 수정되거나, 일부만 복사되거나, 순서가 바뀐
로컬 증거를 사용할 수 있었다.

캠페인 완료 시 작성하는 하나의 매니페스트만으로는 충분하지 않다. 핵심 러너가 끝난 후 Mode
Pack이 파생된 평가, 개선 조치, 재테스트 및 제출 초안 아티팩트를 추가하기 때문이다. 이 매니페스트를
덮어쓰면 이전 무결성 체크포인트가 사라지고 어떤 구성 요소가 각 아티팩트를 추가했는지 불분명해진다.

## 결정

모든 새 Audit Event에는 연속된 시퀀스, 이전 Event 해시 및 정규 JSON 콘텐츠의 SHA-256 해시가
있다. 첫 번째 Event에는 이전 해시가 없다. 추가 또는 검증을 위해 기존 스트림을 로드할 때 Run
ID, 시퀀스, 이전 해시 연결, 콘텐츠 해시 및 오프셋을 포함한 타임스탬프를 검사한다.

`RunStore.seal()`은 `run-integrity.jsonl`에 레코드를 추가한다. 봉인에는 다음 항목이 포함된다.

- Run 및 봉인의 ID, 시퀀스, 타임스탬프
- 이전 봉인의 루트 다이제스트
- 현재 Audit Event 개수와 헤드 해시
- 정규 순서로 정렬된 새로 봉인된 아티팩트 목록
- 각 아티팩트의 경로, 크기, 미디어 타입, SHA-256 다이제스트 및 이용 가능한 출처 정보
- 아티팩트 목록 다이제스트와 전체 봉인 레코드의 최종 루트 다이제스트

증거 JSON의 출처 정보에는 값이 존재할 경우 요청 ID, Tool ID, Worker 실행 ID 및 관련 Audit
Event ID가 포함된다. 다른 아티팩트는 자신의 상대 경로를 인용하는 Event에 연결된다.

첫 번째 봉인은 모든 핵심 실행 아티팩트를 포착한다. 이후 서비스는 전체 Run을 검증하고 새
경로에만 쓰며, 완료 Event를 추가한 다음 이전 루트에 연결된 확장 봉인을 추가해야 한다. 이전에
봉인한 경로는 `RunStore`를 통해 덮어쓸 수 없다. 직접적인 Tool Loop 체크포인트 획득은 원본
Run을 확장한다. Run 외부에 복사된 서명된 Control Plane 체크포인트는 외부 후속 상태로 취급하며,
새 후속 Run은 자체 봉인을 받는다.

다음과 같은 경우 `verify_run_integrity()` 및 `pajin evidence-verify`가 실패한다.

- Event가 편집되거나 제거되거나, 봉인 없이 추가되거나, 순서가 변경된 경우
- 봉인이 편집되거나 일관성 없이 제거되거나, 순서가 변경되거나, 잘못된 루트에 연결된 경우
- 봉인된 아티팩트가 변경되거나 누락되거나 중복되거나 심볼릭 링크이거나 Run 외부에 있는 경우
- 확장 봉인 없이 새 파일이 존재하는 경우

Bug Bounty 보고와 KISA 평가/재테스트는 입력 Run을 읽거나 확장하기 전에 이를 검증한다.

## 결과

이제 로컬 증거 소비자는 재현 가능한 하나의 루트 다이제스트를 받으며 일반적인 변조 및 불완전
복사 조건에서 안전하게 실패한다. 후처리는 기존 체크포인트를 대체하는 대신 유지하고 감사 가능한
체인을 생성한다. 이 ADR 이전에 생성된 기존 Run은 봉인되지 않았으므로 명시적인 마이그레이션 및
신뢰 결정 없이는 무결성을 강제하는 소비자가 이를 수락해서는 안 된다.

SHA-256 체이닝은 Run 생성자의 신원을 인증하지 않는다. 전체 디렉터리와 외부에 앵커링되지 않은
모든 루트를 대체할 수 있는 권한 있는 행위자는 내부적으로 일관된 새 체인을 만들 수 있다. 따라서
프로덕션에서는 별도로 통제되는 서명 레코드, 투명성 서비스 또는 불변 객체 저장소에 루트
다이제스트를 게시해야 한다. 키 관리와 원격 앵커링은 이 변경의 범위에 포함되지 않는다.

## 검증

테스트는 성공적인 핵심 및 확장 봉인, 증거 출처 정보, 봉인된 파일의 덮어쓰기 방지, 변경 및
누락된 아티팩트, 봉인되지 않은 추가 항목, Event 순서 변경 및 콘텐츠 변조, CLI 성공/실패,
수정된 Campaign에 대한 Bug Bounty 거부, 증거 누락에 대한 KISA 거부 및 기존 Tool Loop 후속
동작을 다룬다.
