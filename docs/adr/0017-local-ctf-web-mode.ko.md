# ADR 0017: 로컬 전용 CTF Web Mode 수직 단면

- 상태: 승인됨
- 날짜: 2026-07-13
- 확장: ADR 0018

## 배경

PAJIN 제품 계획에는 범주별 CTF 에이전트, 플래그 검증 및 풀이 문서 생성이 포함된다. 임의의
셸, 크롤러, 브라우저 또는 익스플로잇 권한을 가진 범용 CTF 에이전트에는 아직 충분한 안전
경계가 없다. 챌린지 매니페스트가 에이전트를 공용 대상이나 관련 없는 사설 대상으로 리디렉션할
수 있고, 에이전트가 생성한 경로나 페이로드가 작은 연습 문제를 제한 없는 스캔으로 확대할 수
있기 때문이다.

첫 번째 단면은 대상, 요청 문법, 네트워크 권한 및 성공 조건을 유한하고 테스트 가능한 상태로
유지하면서 완전한 다중 에이전트 및 증거 아키텍처를 입증해야 한다.

## 결정

PAJIN에 `CTFChallenge` 매니페스트를 추가하고 다음 하나의 범주/시나리오 쌍을 지원한다.

- 범주: `web`
- 시나리오: `web.exposed-backup-config`
- 환경: `local-docker`
- 진입점: `http://host.docker.internal:8780/backup/config.json.bak`
- 기대 결과: 소문자 SHA-256 및 공개 `PAJIN{...}` 형식이며, 예상 평문은 절대 사용하지 않음

스키마는 알 수 없는 필드와 그 밖의 모든 호스트, 포트, 경로, 스킴, 쿼리, 환경, 범주 또는
시나리오를 거부한다. 예산은 에이전트 5개, 깊이 1, Tool 호출 1회, 모델 호출 0회, Provider
비용 0, 최대 120초로 고정한다. 매니페스트는 이미지, 실행 파일, 명령, 요청 경로 또는 스코어보드
자격 증명을 제공할 수 없다.

`CTFChallengeService`는 이 계약을 L4 랩 자율성, 정확한 URL 범위, GET 전용 규칙, T1 상한,
사설 네트워크 이그레스 및 단일 Tool과 일치하는 범주 허용 목록을 가진 일반 `Campaign`으로
컴파일한다. 플래그 다이제스트는 Validator를 위해 봉인된 Campaign 메타데이터에 포함되지만
Specialist Tool 입력에는 포함되지 않는다.

`CTFTriagePlannerRuntime`은 타입이 지정된 Web 시나리오를 하나의 `ctf.web-backup-probe`
단계에 매핑한다. Gateway가 생성한 이그레스 프록시가 요청을 디스패치하기 전에 Tool과 신뢰할 수
있는 Worker가 고정 권한부와 경로를 각각 다시 검사한다. Worker는 합성 데이터로 표시된 제한된
JSON 응답만 허용하고 형식 제약을 충족하는 후보를 최대 하나 반환한다.

`CTFFlagValidatorRuntime`은 관찰 결과를 다시 파싱하고 대상 및 챌린지 ID를 검증하며, 동일
Run의 Specialist 증거를 요구하고, 후보를 해시한 다음 상수 시간 다이제스트 비교를 수행한다.
신뢰할 수 없는 해결 주장은 모두 무시한다. 다이제스트가 일치하면 검증된 `CTF-WEB` 결과가 되며,
그 후에도 일반 러너가 선언된 대상과 증거의 결합을 강제한다.

`CTFModePack`은 핵심 Run 무결성 루트를 검증하고 봉인된 Campaign을 원래 챌린지와 대조하며,
결과를 `solved`, `unsolved` 또는 `invalid-flag`로 분류한다. 그런 다음 `ctf-result.json`과
`ctf-writeup.md`를 작성하고, 외부 제출을 수행하지 않았다고 기록하며, 확장 봉인을 추가한다.
`ctf-web-run`은 항상 Docker Worker를 선택하며 플래그가 독립적으로 검증되지 않으면 0이 아닌
코드로 종료한다.

대상 컨테이너는 호스트 루프백 포트 8780에 바인딩되고, 루트가 아닌 사용자로 읽기 전용 파일
시스템에서 실행되며, 모든 capability를 제거하고, 공개 합성 플래그만 포함한다. 강화 프로필은
동일한 백업 경로에 404를 반환한다.

## 결과

이 단면은 실제 HTTP 요청 한 번으로 타입이 지정된 CTF 수집, 범주 라우팅, 제한된 Specialist
권한, 독립적인 플래그 검증, 취약/강화 동작, 증거 출처 정보, 풀이 문서 생성 및 무결성 체인
확장을 입증한다.

이는 크롤러, 범용 Web CTF 솔버, 브라우저 에이전트, 스코어보드 클라이언트, 공용 대상 스캐너
또는 임의 익스플로잇 러너가 아니다. Pwn, 리버싱, 포렌식, 암호학, OSINT 또는 사용자가 제공한
Tool을 지원하지 않는다. 범주나 시나리오를 추가할 때마다 타입이 지정된 새 계약, 고정되었거나
형식적으로 제한된 Tool 문법, 요청 비용 선언, 격리된 픽스처, 독립적인 검증 로직 및 명시적인
안전성 검토가 필요하다.

## 검증

테스트는 정확한 로컬 범위 컴파일, 외부 및 잘못된 경로 거부, 예산 및 평문 플래그 거부, 비활성
권한 부여, 고정 Tool 및 Worker 요청, 취약 및 강화 대상 동작, 올바른/없는/잘못된 후보 분류,
5개 역할 실행, 두 번의 봉인으로 보호되는 증거 무결성, Docker 전용 CLI 선택 및 외부 제출 작업이
없음을 다룬다.
