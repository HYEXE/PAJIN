# ADR-0259: Select Governed Measured AI System-Prompt Disclosure after Phase 24

- Status: Accepted
- Date: 2026-09-01
- Owners: PAJIN architecture and security boundary maintainers
- Scope: Post-Phase 24 checkpoint review and Phase 25 roadmap selection

## Context

Phase 24 completed the exact six-case synthetic Network measurement, independent Replay, bounded
product read, exact-commit Ubuntu real-Docker conformance, and unconditional residue audit. The
next checkpoint must again choose one bounded vertical slice. It must not turn the completed Web
or Network evidence into support for another Domain, and it must not open several provider,
credential, host, artifact, parser, or device boundaries in one phase.

AI now has the strongest remaining repository-owned execution chain:

- AI-001A through AI-001D bind exact model, Tool, scenario, threat-class, request, admitted source,
  fresh-session Replay, three-Control, REDTEAM, and DOMAIN-006 identities without concrete measured
  Ground Truth;
- the code-owned KISA M03 system-prompt-disclosure scenario is a deterministic single-turn POST
  with one exact private check and an existing read-only `ai.chat-probe` Capability;
- `containers/ai-target` implements a deterministic vulnerable and hardened synthetic Chat target,
  target-execution challenge and receipt support, and a fixed `/v1/chat` contract;
- the existing Docker Worker, Gateway, egress-proxy, approval, Permit, KISA Replay, Control, and
  VAL-004A paths already exercise the relevant action and fresh-session boundaries; and
- DOMAIN-006 registers the AI `fresh-session-independent-replay` strategy, threat-class coverage,
  request-unit, and monetary-cost requirements.

The review also confirms the exact gap. The current AI lab compose profile is a maintainer-oriented,
host-published, long-lived target rather than a fresh registry-governed benchmark lifecycle. No
AI-001D concrete Ground Truth binding, AI-specific measured-case authority, disposable M03 Target
Factory, measured source artifact, numeric DOMAIN-006 AI floor, bounded AI product, or exact-commit
residue-free conformance exists. Existing KISA, AI-001, VAL-004A, REDTEAM-002, P0-D2/P0-D2B, and
Walking artifacts retain their own semantics and cannot be relabeled as those missing authorities.

Cloud has mature generic object-storage provider machinery, but CLOUD-001D still lacks a
repository-owned policy emulator, provider-specific translator, disposable account, and truthful
fresh-credential measurement. System lacks a repository-owned authenticated host agent.
Application, Mobile, Cryptography, and Forensics require a new artifact source, parser or analyzer,
sandbox, independent implementation, or device runtime. Those boundaries are larger than the exact
deterministic M03 slice.

The checkpoint also requires a green current-main repository CI baseline before Phase 25 runtime
implementation starts. A timeout or other repository-wide failure must be classified and resolved;
the successful Phase 24 dedicated conformance workflow cannot be substituted for that baseline.

## Decision

Select Phase 25, Governed Measured AI System-Prompt Disclosure, as the next single vertical slice.
Constrain it to the exact code-owned KISA M03 `kisa.model.system-prompt-disclosure` scenario against
the deterministic synthetic `/v1/chat` target. Do not include M06, A04, MCP, RAG, arbitrary prompts,
caller-selected checks, general agent or model testing, external providers, production targets, or
provider credentials.

The private measured-case binding owns the exact prompt, sensitive check, expected vulnerable
outcome, KISA materializer identity, and Control derivation. The public registration carries only
content-addressed case and predecessor references, policy identities, digests, and literal false
authority markers. Raw prompt, check value, transcript, response, target coordinate, session,
request, Worker, receipt, and Target runtime identity remain deployment-private.

Use the existing deterministic AI Target code under a new immutable measured-target profile. The
profile permits only the code-owned M03 case and fixed target mode; callers cannot supply prompt
text, checks, response markers, model aliases, commands, endpoints, images, environment variables,
or provider configuration. Every live Target is a fresh non-root, read-only, capability-dropped
container on an internal network with no published host port. The Worker remains on its proxy-only
network, and only the exact proxy may bridge to the inspected Target coordinate.

The fixed M03 POST is the only application-protocol write in this phase. It remains separately
authorized through the applicable existing Capability, Campaign Scope, approval, one-use Permit or
bounded Grant, Gateway, Worker, and target-receipt paths. Target creation, Ground Truth, Domain
classification, Graph membership, a Replay plan, or product state cannot authorize that POST.

Deliver Phase 25 as four independently reviewable sequential boundaries:

1. **AI-002A: exact M03 measured-case authority.** Register a new AI-specific versioned public
   measured case and separate private Ground Truth binding. Bind the exact AI-001D predecessor,
   M03 scenario and Tool, deterministic target/Worker/proxy image contracts, source/Replay/Control
   protocol, DOMAIN-006 AI plan, cost and request-unit semantics, validation-floor policy, and
   canonical order. This boundary builds no image, creates no Target, selects no runtime provider,
   issues no approval, Permit, or Grant, runs no Tool or Worker, records no measurement, and exposes
   no product.
2. **AI-002B: registry-governed disposable M03 source measurement.** Bind deployment-observed OCI
   identities, create one fresh internal no-published-port vulnerable Target lifecycle, and execute
   only the exact approved M03 source through the existing action path. Reopen the existing AI-001C
   source/admission authority without adding Graph semantics, seal target, proxy, Worker, request,
   response, target-receipt, transcript, and cleanup evidence, and keep all raw material private. A
   code-owned denial set must reject substituted scenario, prompt, check, mode, image, route, Scope,
   or authority before dispatch.
3. **AI-002C: independent fresh-session Replay, Controls, and AI floor.** Rebuild the AI-001D and
   VAL-004A boundaries with two supporting fresh-session Replay repetitions and the exact Baseline,
   Negative Control, and Counterfactual order. Source, Replay, and Control session, request,
   authorization, Worker execution, Evidence, and Target lifecycle identities must be disjoint
   where their existing contracts require independence. Contextfully reopen the private case before
   evaluating the exact DOMAIN-006 AI metric order. The deterministic local lab's request units,
   Tool calls, and zero model-provider cost are measured facts, not inferred defaults or N/A. Target
   cleanup and zero residue remain mandatory even where the registered read-only cleanup metric is
   N/A. A passing floor neither confirms the AI-001C Observation nor creates a Finding.
4. **AI-002D: bounded Operator product read and exact conformance.** Seal only public-safe case
   references, ordered aggregate metrics, applicability, floor state, and explicit false-authority
   markers into an AI-only product. Expose it through a deployment-pinned zero-argument reader and
   one authenticated Operator-only non-cacheable read. Complete the phase only after an exact-clean
   Ubuntu real-Docker workflow executes the source, two Replay repetitions, three Controls, denial
   set, cleanup, fresh-process product reload, and unconditional residue audit successfully.

The current-main repository CI must be green before AI-002A runtime implementation begins. Fixing
or revalidating that baseline is a prerequisite, not an authority to weaken Phase 24 tests or skip
Phase 25 conformance.

## Consequences

- AI becomes the next measured Domain slice through one deterministic, synthetic, single-turn
  threat class rather than an arbitrary provider or model benchmark.
- Existing target, Worker, KISA Replay, Control, and floor machinery can be composed, but the joins
  require new AI-specific public/private authority and lifecycle contracts.
- Sensitive prompt and check material stays outside public products and Graph prose even though its
  digest and code-owned identity may participate in verification.
- M06 and stateful A04 remain deferred. Their inclusion would enlarge the safety-policy and
  multi-turn memory/session boundary and requires a later versioned decision.
- The P0-D2B deterministic RAG/MCP chain remains a separate Finding-oriented benchmark. It does not
  satisfy the KISA fresh-session AI plan and is not reinterpreted as M03 evidence.
- A perfect synthetic score does not establish production model safety, prompt secrecy, general AI
  coverage, provider quality, or external-target authority.

## Rejected alternatives

### Measure M03, M06, and A04 together

Rejected because A04 adds persistent multi-turn state and M06 adds a distinct safety-policy claim.
The single-turn M03 case has the smallest exact request, Target-state, and Ground Truth boundary.

### Reuse P0-D2B or Walking results as AI-002 measurement

Rejected because those contracts describe a deterministic RAG/MCP authorization-failure chain and
Finding-oriented benchmark semantics. They do not provide the M03 scenario, fresh-session KISA
Replay, three-Control evidence, or AI-001D identity required by this phase.

### Use an external LLM provider

Rejected because provider credentials, pricing, nondeterminism, data retention, model revision,
tenant isolation, and production network policy would dominate the first measured AI boundary.

### Select Cloud, System, or an offline parser Domain first

Rejected because each still requires a new provider-specific emulator or translator, host agent,
artifact custody source, parser or analyzer, independent implementation, sandbox, or device
runtime. The repository already owns the exact deterministic M03 Target and action chain.

### Extend AI-001D or REDTEAM-002 in place

Rejected because both accepted identities deliberately stop before concrete Ground Truth and
measurement. Changing their meaning would make historical artifacts ambiguous and couple a new
runtime authority to established generic contracts.

### Start Phase 25 while current-main CI is red

Rejected because the new phase needs a trustworthy regression baseline. A dedicated Phase 24
workflow proves only its exact conformance boundary and cannot hide a repository-wide test failure.

## Security and authority impact

This ADR selects work; it does not build an image, create a Target or network, select a provider,
materialize a prompt, issue an approval, Permit, or Grant, run a Tool or Worker, call a model, write
the Graph, record a measurement, satisfy a floor, confirm a Finding, or expose a product.

Future AI-002 execution is restricted to the code-owned synthetic M03 request and internal
deterministic target. Caller-selected prompt text, checks, markers, sessions, targets, endpoints,
models, provider settings, credentials, images, commands, or environment fail closed. No Internet,
external provider, production endpoint, arbitrary Tool or plugin, credential, filesystem, shell,
RAG, MCP, memory mutation, M06/A04 behavior, report, delivery, or cross-domain authority is added.

Existing AI-001C Graph admission remains neutral provenance. AI-002 cannot reinterpret it as Ground
Truth, confirmation, a Finding, or execution authority. Existing approvals, consumed Permits,
bounded Grants, Replay plans, Control records, and product reads never authorize another action.

## Compatibility and rollback

The roadmap decision is additive. Existing AI-001A/B/C/D, KISA, VAL-004A, REDTEAM-002, P0-D2,
P0-D2B, Walking, DOMAIN-006, Capability, Campaign, approval, ActionPermit, Grant, Gateway, Worker,
Graph, Finding, benchmark, product, and artifact-reader identities remain unchanged. No migration
is required.

Rollback removes Phase 25 from `PLAN.md` and supersedes this roadmap decision. Once implementation
exists, rollback stops producing additive AI-002 artifacts and removes its measured Target,
provider, product, tests, and workflow without rewriting accepted Runs, Graph events, KISA evidence,
or existing benchmark records.

## Verification requirements

Each boundary must cover exact M03 scenario, threat class, Tool, target mode, private prompt/check,
Control membership and order, source/Replay/Control separation, canonical wire and strict-model
validation, digest and nested-model substitution, public/private leakage, image/profile/route drift,
caller-selected configuration, session and request reuse, stale approval, Permit or Grant reuse,
missing target receipt, cost and request-unit drift, incomplete cleanup, residue, false confirmation,
Graph/Finding/report escalation, and literal false execution authority.

AI-002B through AI-002D additionally require opt-in real-Docker tests. The Phase 25 Exit Gate
requires a green current-main repository CI baseline and an exact-commit Ubuntu workflow in which
all required M03 source, Replay, Control, denial, product-read, cleanup, and unconditional residue
checks succeed. Fake Workers, in-process target calls, historical KISA evidence, or a non-Docker
fixture do not count as that conformance evidence.
